# reqrec — 社内サイトの操作から Python スクリプトを作る Web アプリ

Edge の IE モードで使う社内の `http://` サイトについて、操作したときの通信（HAR ファイル）から、同じ操作を
自動で行う Python スクリプト（`requests` + `BeautifulSoup`）を作ります。ログイン、毎回変わるセッション ID や
トークン、別タブ・子画面で開く画面、カレンダーで選ぶ日付、Excel / CSV のダウンロードにも対応しています。

社内 LAN の JupyterLab サーバーで、ターミナルから `flask` コマンドで起動し、自分の PC のブラウザで使います。

## 必要なもの

- 社内 LAN の JupyterLab サーバー（Python 3.10 以上）
- `reqrec.py` と `requirements.txt`（アプリは `reqrec.py` の 1 ファイルです）
- 自分の PC（Windows）の Edge と、IE11 の F12 開発者ツール `C:\Windows\System32\F12\IEChooser.exe`
  （HAR ファイルの保存に使います）

## 準備（最初の 1 回）

`reqrec.py` と `requirements.txt` をサーバーの同じフォルダ（例: `~/reqrec`）に置き、JupyterLab のターミナルで
ライブラリを入れます。

```bash
cd ~/reqrec
```

```bash
pip install -r requirements.txt
```

次に、ログインに使うパスワードを決めます。`reqrec.py` の先頭近くに平文で書いてあります（初期値は `adminpass`）。
推測されにくい値に書き換えてください（初期値のまま起動すると、注意が表示されます）。

```python
GUI_PASSWORD = "adminpass"
```

環境変数 `REQREC_GUI_PASSWORD` を設定した場合は、そちらが優先されます。

## 起動と終了

JupyterLab のターミナルで、`reqrec.py` のあるフォルダに移動して起動します。ポート番号（`8765`）は空いているものを
使ってください。

```bash
flask --app reqrec run --port 8765
```

自分の PC のブラウザから `http://<サーバーの IP アドレス>:8765/` で開くときは、`--host 0.0.0.0` も付けます
（付けないと、サーバーの中からしか開けません）。

```bash
flask --app reqrec run --host 0.0.0.0 --port 8765
```

- 開くとログイン画面が出るので、パスワードを入れます。ログインは 12 時間有効で、画面右上の [ログアウト] でも終われます。
- 終了は、ターミナルで `Ctrl+C` です。
- 起動時に Flask が「This is a development server.」と表示しますが、自分専用で使う分には問題ありません。
- 作業フォルダは、起動したフォルダの `reqrec_work` です。変えるときは、起動の前に
  `export REQREC_WORKDIR=~/reqrec_work` のように指定します。

## 使い方

### 1. HAR ファイルを保存する（自分の PC）

Edge の IE モードのタブは IE11 のエンジンで動いているため、Edge の開発者ツール（F12）は使えません。
IE11 の F12 開発者ツールで通信を保存します。

1. Edge で社内サイトを開き、記録したい操作の最初の画面（ログイン画面など）まで表示します。
2. `C:\Windows\System32\F12\IEChooser.exe` を起動し、一覧からそのタブを選びます。F12 開発者ツールが開きます。
3. 「ネットワーク」タブを開き、記録が止まっていれば ▶（緑の三角）で開始します。
4. いつもどおりサイトを操作します（ログイン → 欲しいデータの画面まで。Excel / CSV のダウンロードも）。
5. 「HAR としてエクスポート」（保存のアイコン、`Ctrl+S`）で `.har` ファイルを保存します。

- F12 開発者ツールを開く前の通信は入りません。ログインから記録するときは、ログイン画面で開いてから操作します。
- 別タブ・別ウィンドウで開いた画面の通信は、そのタブの F12 開発者ツールにしか入りません。そのタブも
  IEChooser.exe で選んで HAR を保存し、次の 2 で複数のファイルをまとめて選びます（時刻の順に 1 つの流れにします）。
- 記録されるのは `http://` のサイトです。`https://` のサイトは対象外です。
- HAR にはパスワード・Cookie・トークンがそのまま入っています。人に渡さず、使い終わったら削除してください。

### 2. スクリプトを作る（かんたん画面）

1. ブラウザで reqrec を開いてログインすると、かんたん画面が表示されます。
2. 下の方の **[HAR ファイルから作る…]** を押して、保存した `.har` を選びます（複数選べます）。
3. 自動で解析されてスクリプトができあがり、作業フォルダの `scripts/` に保存されます。

できあがりの画面でできること:

- **[⬇ スクリプトをダウンロード]** — 自分の PC に保存します。
- **[▶ 試しに実行する]** — サーバーで実行して、結果をその場で確認します。どの手順まで進んだかも表示され、
  失敗したときは、よくある原因の説明が出ます。Excel / CSV のダウンロードは作業フォルダの `outputs/` に保存され、
  [結果をファイルに保存] で表示された結果も保存できます。
- **[詳細を見る・変更する]** — 次の「詳細設定」を開きます。
- 「確認してください」の欄が出たときは、内容を読んでください（実行すると失敗するかもしれない点です）。

> 画面上部の「記録機能の準備ができていません」の表示と、[● 記録をはじめる] が押せないのは正常です。
> 記録用ブラウザは reqrec を動かしている PC（サーバー）の上で開くため、この使い方では使いません。
> HAR ファイルから作ります。

### 3. 中身を確認して変える（詳細設定）

画面右上の **[詳細設定を表示]**（できあがりの画面では [詳細を見る・変更する]）で開きます。上から 4 つの欄があります。

1. **手順の一覧** — スクリプトが使う通信の一覧です。チェックで使う・使わないを切り替え、「結果」でスクリプトの
   最後に表示する画面を選べます。行をクリックすると、送ったデータと受け取ったデータが見られます。
   「使わない通信も表示」にチェックを入れると、自動で外した画像や解析サービスなどの通信も出ます。
2. **設定** — 手順の間の待ち時間、タイムアウト、パスワードをスクリプトに書き込まない設定などです。変えたら
   **[⚙ 設定から作り直す]** を押すと、同じファイル名のまま作り直して保存します（コードを手で書き換えていたときは、
   置きかえる前に確認します）。
3. **コード** — その場で直接書き換えて **[保存]** できます（Tab キーで空白 4 つ、`Ctrl+S` で保存）。ファイル名を
   変えて保存すると、別の名前で保存します。[保存した内容に戻す] で書き換えを取り消せます。
4. **試しに実行する** — 保存していない変更があるときは、保存してから実行します。

新しい HAR ファイルを読み込むと、詳細設定で変えた設定は最初の状態に戻ります。

### 4. 作ったスクリプトを使う

サーバーのターミナルで、そのまま実行できます（必要なライブラリは準備で入っています）。

```bash
cd ~/reqrec/reqrec_work/scripts
```

```bash
python scrape_xxx.py
```

- 実行中は、どの手順まで進んだかが 1 手順 1 行で表示されます（`[2/9] OK  POST /Login.aspx (200)  「メニュー」`）。
  最後は `[完了] すべての手順が終わりました（9 手順）` です。失敗したときは、止まった手順が `[3/9] 失敗 …` と出ます。
- 最後の画面の結果（タイトル、JSON など）は標準出力に出ます。`python scrape_xxx.py > result.txt` で保存できます。
- Excel / CSV のダウンロードは、サーバーが付けた名前で、実行したフォルダ（環境変数 `REQREC_OUTPUT_DIR` があれば
  そのフォルダ）に保存されます。
- 記録したパスワードは、スクリプトにそのまま書き込まれます。詳細設定で「パスワードなどをスクリプトに書き込まず、
  実行するときに入力する」をオンにして作り直すと、実行するときに環境変数で渡す形になります。
- 毎回変わるセッション ID やトークンは、実行のたびに画面から取り出して使います。カレンダーなどで選んだ値
  （日付・取引先コードなど）は、記録したときの値を送ります。日付を毎回「今日」にしたいときは、その行を
  書き換えます（例: `'dateFrom': time.strftime('%Y/%m/%d'),`。`time` はスクリプトの先頭で読み込み済みです）。
- 取り出したデータを加工・保存する処理は、`main()` の最後に書き足します。
- 別の PC で動かすときに必要なのは、Python と `pip install requests beautifulsoup4` だけです。

## 作業フォルダ

| フォルダ | 中身 |
|---|---|
| `uploads/` | 読み込んだ HAR ファイルのコピー |
| `scripts/` | 作ったスクリプト。[試しに実行する] はここのファイルを実行します |
| `outputs/` | [試しに実行する] でダウンロードされた Excel / CSV と、[結果をファイルに保存] で保存した結果 |
| `recordings/` | この使い方では使いません |

HAR とスクリプトにはパスワードが入っています。作業フォルダは共有フォルダに置かず、不要になったら削除してください。

## パスワードとセキュリティ

- 画面は `http://` なので、パスワードや HAR の中身は暗号化されずに社内 LAN を流れます。Windows のログオンと
  同じパスワードは使わないでください。
- パスワードを 5 回続けて間違えると、その PC からは 60 秒間ログインできなくなります。
- `GUI_PASSWORD = ""`（空）にすると、他の PC からは使えなくなります（サーバーの中からだけ使えます）。
- GUI のパスワードは、[試しに実行する] で動かすスクリプトには渡しません。
- スクリプトはサーバーで実行されるため、社内サイトから見た接続元はサーバーになります。

## 困ったとき

**Q. 起動すると「Address already in use」と出る。**
そのポートは使われています。`--port 8766` のように別の番号で起動してください。

**Q. 自分の PC のブラウザで開けない。**
`--host 0.0.0.0` を付けて起動したか確認してください。付けていても開けないときは、サーバーのそのポートが
ファイアウォールで閉じられている可能性があります（IT 担当に確認してください）。

**Q. ログインできない。**
`reqrec.py` の `GUI_PASSWORD`（環境変数 `REQREC_GUI_PASSWORD` があればそちら）を確認してください。5 回続けて
間違えたときは、60 秒待ってから入れ直します。

**Q. HAR を読み込むと「スクリプトにできる通信が記録にありませんでした」と出る。**
HAR に `http://` の画面の通信が入っていません。F12 開発者ツールの「ネットワーク」タブを開いて記録を始めてから
操作したか、`https://` のサイトではないかを確認してください。

**Q. F12 開発者ツールの「ネットワーク」で「ネットワーク コレクション エージェントを開始できませんでした」と出る。**
その PC の Windows の構成では、F12 開発者ツールで通信を保存できません。IT 担当に相談してください。

**Q. [試しに実行する] でエラーになる。**
画面に出る説明を読んでください。よくある原因は次のとおりです。

- サーバーから社内サイトに接続できない（サーバーのネットワークの設定）
- ログインに失敗した（パスワードが変わった）
- サイトの画面が変わった（HAR を取り直して作り直す）
- 統合 Windows 認証のサイト（開くと自動でログインされるサイト）は、サーバーのアカウントで認証されるため、
  そのままでは動かないことがあります

**Q. カレンダーで日付を選ぶ画面や、子画面で値を選ぶ画面は使える？**
使えます。選んだ値は、そのあとの [検索] などで送られた値として HAR に入り、スクリプトはその値を送ります。
選ばずに初期値のままだった欄は、実行のたびに画面の初期値を読み取ります。
