# reqrec — LAN環境内のサイトの操作から Python スクリプトを作るアプリ

Edge の IE モードで使う LAN環境内の `http://` サイトを、記録用ブラウザでいつもどおり操作するだけで、同じ操作を
自動で行う Python スクリプト（`requests` + `BeautifulSoup`）を作ります。ログイン、毎回変わるセッション ID や
トークン、別タブ・子画面で開く画面、カレンダーで選ぶ日付、Excel / CSV のダウンロードにも対応しています。

自分の Windows PC で `python reqrec.py` と起動して使います。

- 記録用ブラウザは、Edge の IE モードと同じエンジン（IE エンジン）を Python から動かしています。
  reqrec 専用の exe はありません。動くのは Python 本体と `reqrec.py` だけです。
- Windows の設定・レジストリ・証明書は変更しません。記録のための中継（プロキシ）は、記録用ブラウザ自身にだけ
  設定します。Edge やほかのアプリには影響しません。

## 必要なもの

- Windows 10 / 11 の PC
- Python 3.10 以上（インストール済みのもの）
- `reqrec.py` と `requirements.txt`（アプリは `reqrec.py` の 1 ファイルです）

サイトの中で古い ActiveX の部品（32 ビット）を使っている場合は、32 ビット版の Python が必要です。ふつうの
画面・入力・JavaScript だけのサイトなら、64 ビット版の Python で動きます。

## 準備（最初の 1 回）

`reqrec.py` と `requirements.txt` を同じフォルダ（例: `C:\reqrec`）に置き、コマンドプロンプトでそのフォルダに
移動して、ライブラリを入れます。

```bash
cd C:\reqrec
```

```bash
python -m pip install -r requirements.txt
```

- ユーザーフォルダに置いた exe の実行が止められている PC では、仮想環境（venv）を作らず、インストール済みの
  Python でそのまま入れてください（仮想環境の `python.exe` や `flask` コマンドは、ユーザーフォルダに置かれる
  exe です）。`python reqrec.py` で起動するので、ほかの exe は使いません。
- 権限の関係で入れられないときは、`python -m pip install --user -r requirements.txt` を試してください。

## 起動と終了

`reqrec.py` のあるフォルダで起動します。

```bash
python reqrec.py
```

- ブラウザ（Edge）が自動で開き、かんたん画面が表示されます。開かないときは、コマンドプロンプトに表示された
  アドレス（`http://127.0.0.1:8765` など）をブラウザで開きます。
- ポート 8765 が使われているときは、8766、8767 … の空いている番号で起動します。
- 終了は、コマンドプロンプトで `Ctrl+C` です。
- この PC の中から使う分には、ログインもパスワードも不要です。
- 記録やスクリプトは、`reqrec.py` と同じフォルダの `reqrec_work` に保存されます（[作業フォルダ](#作業フォルダ)）。

Flask のコマンドで起動することもできます（ブラウザは自動では開きません。作業フォルダは起動したフォルダの
`reqrec_work` です）。

```bash
python -m flask --app reqrec run --port 8765
```

## 使い方

### 1. 記録する（かんたん画面）

1. **[● 記録をはじめる]** を押します。記録用ブラウザ（タイトルに「記録中」と付いたウィンドウ）が開きます。
2. 記録用ブラウザで、いつもどおりサイトを操作します（ログイン → 欲しいデータの画面まで。
   Excel / CSV のダウンロードも）。サイトのアドレスは、記録用ブラウザのアドレス欄に入れて開けます。
3. 記録用ブラウザの赤い **[■ 記録をおわる]** を押します（ウィンドウを閉じても同じです）。
   自動で解析されてスクリプトができあがり、作業フォルダの `scripts/` に保存されます。

- 「開くサイトのアドレス」に入れておくと、記録用ブラウザがそのページを開いた状態で始まります。
- 別タブ・別ウィンドウで開く画面（`window.open`、`target=_blank`）は、記録用ブラウザの中の新しいタブとして開き、
  子画面（`showModalDialog`）もそのまま開きます。どちらの通信も記録されます。
- 記録用ブラウザは、毎回ログインしていない状態で始まります。ログインから操作してください。
- 記録されるのは `http://` のページの通信です。`https://` のページは表示されますが、記録されません。
- **表示モード**: 記録用ブラウザで画面が崩れるときだけ変えます（IE8 相当 / IE11 相当 / IE11 強制）。
  記録用ブラウザの中だけで切り替わり、選んだモードは次回も使われます。
- 記録中は、かんたん画面に記録した通信の件数が表示されます。かんたん画面の [■ 記録をおわる] でも終われます。
  [やめる] を押すと、記録を破棄します。

### 2. できあがりの画面

- **[⬇ スクリプトをダウンロード]** — スクリプトを保存します。
- **[保存先フォルダを開く]** — `scripts/` フォルダをエクスプローラーで開きます。
- **[▶ 試しに実行する]** — この PC で実行して、結果をその場で確認します。どの手順まで進んだかも表示され、
  失敗したときは、よくある原因の説明が出ます。Excel / CSV のダウンロードは作業フォルダの `outputs/` に保存され、
  [結果をファイルに保存] で表示された結果も保存できます。
- **[詳細を見る・変更する]** — 次の「詳細設定」を開きます。
- 「確認してください」の欄が出たときは、内容を読んでください（実行すると失敗するかもしれない点です）。

### 3. 中身を確認して変える（詳細設定）

画面右上の **[詳細設定を表示]**（できあがりの画面では [詳細を見る・変更する]）で開きます。上から 4 つの欄があります。

1. **手順の一覧** — スクリプトが使う通信の一覧です。チェックで使う・使わないを切り替え、「結果」でスクリプトの
   最後に表示する画面を選べます。行をクリックすると、送ったデータと受け取ったデータが見られます。
   「使わない通信も表示」にチェックを入れると、自動で外した画像や解析サービスなどの通信も出ます。
2. **設定** — 手順の間の待ち時間、タイムアウト、パスワードをスクリプトに書き込まない設定などです。変えたら
   **[⚙ 設定から作り直す]** を押すと、同じファイル名のまま作り直して保存します（コードを手で書き換えていたときは、
   置きかえる前に確認します）。
3. **コード** — その場で直接書き換えて **[保存]** できます（Tab キーで空白 4 つ、`Ctrl+S` で保存）。ファイル名を
   変えて保存すると、別の名前で保存します。[保存した内容に戻す] で書き換えを取り消せます。
4. **試しに実行する** — 保存していない変更があるときは、保存してから実行します。

新しく記録すると（または HAR ファイルを読み込むと）、詳細設定で変えた設定は最初の状態に戻ります。

### 4. 作ったスクリプトを使う

コマンドプロンプトで、そのまま実行できます（必要なライブラリは準備で入っています）。

```bash
cd C:\reqrec\reqrec_work\scripts
```

```bash
python scrape_xxx.py
```

- 実行中は、どの手順まで進んだかが 1 手順 1 行で表示されます（`[2/9] OK  POST /Login.aspx (200)  「メニュー」`）。
  最後は `[完了] すべての手順が終わりました（9 手順）` です。失敗したときは、止まった手順が `[3/9] ERROR …` と出て、
  その下にエラーの詳細が出ます。どちらも、URL や Cookie の値、画面から取り出した値（セッション ID など）は `***` に
  置き換えて表示します。ファイルを保存できなかったとき（前回の Excel ファイルを開いたままのときなど）も、その手順が
  `ERROR` になります。
- 最後の画面の結果（タイトル、JSON など）は標準出力に出ます。タイトルの無い画面では、ステータスコードと手順
  （`200 GET /app/list.do`）を表示します。`python scrape_xxx.py > result.txt` で保存できます。
- Excel / CSV のダウンロードは、サーバーが付けた名前で、実行したフォルダ（環境変数 `REQREC_OUTPUT_DIR` があれば
  そのフォルダ）に保存されます。サーバーが名前を付けないときは URL の末尾の名前を使います（`report.xls;jsessionid=…`
  は `report.xls`）。
- スクリプトの先頭の「入力値」の欄に、記録したときに画面で入力・選択した値（ユーザー ID、パスワード、検索の
  条件など）が入力欄ごとにまとまっています。書き換えると、その欄だけ別の条件で実行できます（開始日と終了日のように
  同じ値を入れた欄も別々です）。画面のスクリプトが同じ値を別の通信（Excel 出力など）でも送るときは、そちらにも
  書き換えた値が送られます（日付や数字などの短い値は、`txtDateFrom` と `dateFrom` のように項目名が似ているときだけ）。
  Shift_JIS などの画面で日本語を入力した欄も、日本語のまま書き換えられます（送るときに画面の文字コードに変換します）。
- 記録したパスワードは、この「入力値」にそのまま書き込まれます。詳細設定で「パスワードなどをスクリプトに書き込まず、
  実行するときに入力する」をオンにして作り直すと、実行するときに環境変数で渡す形になります。
- 毎回変わるセッション ID・トークン・Cookie は、実行のたびにログインから取り直します。URL の途中やクエリに入る
  セッション ID（英字だけのもの・短いものも含む）も、ログインしたあとの転送先の URL などから取り直します。
  同じ名前の Cookie が画面ごとに別々に発行されるサイト（ポータルから業務画面に移るときなど）や、Cookie の属性が
  壊れているサイト（空の Domain、数字でない Max-Age など）でも、記録したブラウザと同じ Cookie を送ります。
- 画面を開いたときにサーバーが入れておいた値や、画面のスクリプトが入力欄に入れた値（出荷予定日、その日の日付など）は、
  実行のたびに画面やその応答から取り直します（取り直す場所が見つからないときは、記録したときの値を送ります）。
  一覧（ポップアップ、画面の中の一覧、行ごとの［開く］ボタン）やカレンダーで選んだ値（日付・取引先コードなど）は、
  一覧の並びが変わっても記録したときの値を送ります。日付を毎回「今日」にしたいときは、その行を書き換えます
  （例: `'dateFrom': time.strftime('%Y/%m/%d'),`。`time` は読み込み済みです）。
- うまく動かないときは、環境変数 `REQREC_DEBUG` を `1` にして実行すると、手順ごとに「送る値をどこから取ったか」
  「どの Cookie（domain / path）を使ったか」が表示されます。値そのもの（パスワード・Cookie の中身）は表示しません。

```bash
set REQREC_DEBUG=1
```
- 取り出したデータを加工・保存する処理は、`main()` の最後に書き足します。
- 別の PC で動かすときに必要なのは、Python と `pip install requests beautifulsoup4` だけです。

### HAR ファイルから作る

IE11 の F12 開発者ツールで保存した HAR ファイルからも作れます。かんたん画面の **[HAR ファイルから作る…]** を
押して `.har` を選びます（別タブの HAR は、まとめて選ぶと時刻の順に 1 つの流れにします）。

1. Edge の IE モードでサイトを開き、`C:\Windows\System32\F12\IEChooser.exe` でそのタブを選びます。
2. F12 開発者ツールの「ネットワーク」タブで ▶（緑の三角）を押して記録を始め、いつもどおり操作します。
3. 「HAR としてエクスポート」（保存のアイコン、`Ctrl+S`）で `.har` ファイルを保存します。

HAR にはパスワード・Cookie・トークンがそのまま入っています。人に渡さず、使い終わったら削除してください。

## 作業フォルダ

`reqrec.py` と同じフォルダの `reqrec_work` です（環境変数 `REQREC_WORKDIR` で変えられます）。

| フォルダ | 中身 |
|---|---|
| `recordings/` | 記録用ブラウザで記録した通信（`rec_日時.json`） |
| `uploads/` | 読み込んだ HAR ファイルのコピー |
| `scripts/` | 作ったスクリプト。[試しに実行する] はここのファイルを実行します |
| `outputs/` | [試しに実行する] でダウンロードされた Excel / CSV と、[結果をファイルに保存] で保存した結果 |
| `logs/` | 記録用ブラウザのログ（うまく動かないときの調査用） |

記録・HAR・スクリプトにはパスワードが入っています。作業フォルダは共有フォルダに置かず、不要になったら削除してください。

## 安全のために

- Windows の設定・レジストリ・証明書は変更しません。記録用ブラウザは、この PC の中だけで待ち受ける中継
  （`127.0.0.1`）を通して通信し、その中継は記録用ブラウザ自身にだけ設定します。
- reqrec が通信する相手は、記録用ブラウザで開いたサイトと、[試しに実行する] で動かしたスクリプトが開くサイト
  だけです。インターネット上のサービスには接続しません。
- 記録用ブラウザは、記録を始めるたびにログインしていない状態で始まり、記録中に受け取った Cookie を残しません。
- 他の PC から画面を開けるようにする場合（`python reqrec.py gui --host 0.0.0.0 --port 8765`）は、ログインの
  パスワードが必要です。`reqrec.py` の先頭近くの `GUI_PASSWORD = "adminpass"` を推測されにくい値に書き換えて
  ください（環境変数 `REQREC_GUI_PASSWORD` があればそちらが優先されます。`""` にすると他の PC からは使えません）。
  他の PC からは HAR ファイルの読み込みだけができ、記録はできません（記録用ブラウザは reqrec を動かしている
  PC に開くため）。画面は `http://` なので、パスワードや記録の中身は暗号化されずに LAN環境内を流れます。

## 困ったとき

**Q. [● 記録をはじめる] が押せない。**
reqrec を動かしている Windows の PC で、その PC のブラウザから開いているか確認してください。他の PC から開いた
画面や、Windows 以外で動かしたときは、HAR ファイルからだけ作れます。

**Q. 「記録用ブラウザを開けませんでした」と出る。**
もう一度 [● 記録をはじめる] を押してください。何度やっても同じときは、PC を再起動してから試してください。
作業フォルダの `logs/` に記録用ブラウザのログがあります。

**Q. 記録中の件数が増えない。**
記録用ブラウザ（タイトルに「記録中」と付いたウィンドウ）でサイトを開いているか確認してください。
`https://` のページは記録されません。

**Q. 記録用ブラウザで画面が崩れる・ボタンが動かない。**
かんたん画面の「表示モード」を変えて、もう一度記録してください。ActiveX の部品を使う画面は、32 ビット版の
Python で reqrec を動かす必要があります。

**Q. 「スクリプトにできる通信が記録にありませんでした」と出る。**
`http://` の画面を開いた通信が記録にありません。記録用ブラウザで `http://` のページを開いて操作したか
確認してください。

**Q. [試しに実行する] でエラーになる。**
画面に出る説明を読んでください。よくある原因は次のとおりです。

- ログインに失敗した（パスワードが変わった）
- サイトの画面が変わった（記録し直して作り直す）
- 統合 Windows 認証のサイト（開くと自動でログインされるサイト）は、[試しに実行する] の画面の説明に従って
  ユーザー名とパスワードを入れる必要があることがあります

**Q. カレンダーで日付を選ぶ画面や、子画面で値を選ぶ画面は使える？**
使えます。選んだ値は、そのあとの [検索] などで送られた値として記録され、スクリプトはその値を送ります。
選ばずに初期値のままだった欄は、実行のたびに画面の初期値を読み取ります。

**Q. ウイルス対策ソフトに止められないか心配。**
reqrec 専用の exe はなく、動くのはインストール済みの Python 本体と `reqrec.py` だけです。会社のルールで確認が
必要な場合は、`reqrec.py`（テキストファイル）の中身を IT 担当に見てもらえます。
